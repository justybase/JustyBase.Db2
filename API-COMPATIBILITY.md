# API compatibility policy

The public surface is tracked mechanically so accidental API changes fail the build.

## Snapshots

Each shipped assembly has a committed snapshot generated by reflection in `src/Db2.Tests/ApiSurfaceTests.cs`:

| Package | Snapshot |
| --- | --- |
| `JustyBase.Db2` | [`api/JustyBase.Db2.txt`](api/JustyBase.Db2.txt) |
| `JustyBase.Db2.IBMCompat` | [`api/JustyBase.Db2.IBMCompat.txt`](api/JustyBase.Db2.IBMCompat.txt) |

Snapshots include public and protected members. Protected members are extension points for subclassing consumers, so they are part of the contract. Init-only properties are rendered as `init`.

The SDK package validation (`EnablePackageValidation`) runs on every pack. There is no baseline package yet, because no stable version has been published. The snapshots are therefore the primary API gate for the alpha.

## Public namespaces

| Namespace | Assembly | Status |
| --- | --- | --- |
| `JustyBase.Db2` | `JustyBase.Db2` | Native API: `Db2Config`, `Db2Session`, `Db2Pool`, results, errors, `Db2ColumnMetadata`. |
| `JustyBase.Db2.AdoNet` | `JustyBase.Db2` | ADO.NET provider: connection, command, reader, transaction, parameters, importer. |
| `JustyBase.Db2.Types` | `JustyBase.Db2` | `SqlType` codes and `SqlTypeNames` helpers used by `Db2ColumnMetadata.SqlType`. |
| `IBM.Data.Db2` | `JustyBase.Db2.IBMCompat` | Source-compatible facade for migrations. Separate package, separate snapshot. |

Protocol, DRDA/DDM encoding, converters, packet types and Kerberos/SECMEC internals are **internal**. They are not part of any compatibility commitment. Tests and the first-party IBM compatibility package reach them through `InternalsVisibleTo`.

## Stability tiers

| Tier | Surface | Alpha policy |
| --- | --- | --- |
| Supported alpha | `Db2Config`, `Db2Session`, `Db2Pool`, structured errors, `Db2ColumnMetadata`, typed values, the ADO.NET provider | Changes must be deliberate, documented in the CHANGELOG and reflected in the snapshot. |
| Experimental | `IBM.Data.Db2` source-compatibility facade and IBM-shaped bulk-copy helpers | May change between alpha releases; gaps are listed in the migration guide. |

Before 1.0, Semantic Versioning permits breaking changes through minor-version changes. `0.1.0-alpha.3` is intentionally not presented as a stable contract.

## Extension points

These members exist for subclassing and are part of the snapshot:

- `Db2AdoConnection`: `protected` `OnInfoMessage`, `CloseAsync(bool)`, `Dispose(bool)`, `BeginDbTransaction(Async)`, `CreateDbCommand`; `protected internal` `TranslateProviderError` and `TranslateOperationCancellation`, which the compatibility package overrides.
- `Db2AdoCommand`, `Db2AdoTransaction`, `Db2AdoParameterCollection`: the standard `DbCommand`, `DbTransaction` and `DbParameterCollection` overrides.

The compatibility package receives two IBM-shaped importer knobs through `InternalsVisibleTo("JustyBase.Db2.IBMCompat")`. The core package does not expose them publicly.

## Commands

```bash
dotnet test src/Db2.Tests/Db2.Tests.csproj --filter FullyQualifiedName~ApiSurfaceTests
API_SURFACE_UPDATE=1 dotnet test src/Db2.Tests/Db2.Tests.csproj --filter FullyQualifiedName~ApiSurfaceTests
```

The second command regenerates both snapshots. Use it only for a reviewed public-surface change.

## Change process

1. Decide whether the API change is intentional.
2. Update implementation and tests.
3. Update `README.md`, `CHANGELOG.md`, the migration guide and affected package READMEs.
4. Regenerate the affected snapshot(s) in the same reviewed change.
5. Provide migration or deprecation guidance for supported-alpha consumers where practical.

Do **not** regenerate a snapshot merely to make CI green.

Neither package is published. Publication is a separate, explicit release decision.
